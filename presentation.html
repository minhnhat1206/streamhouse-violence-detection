04 / Data Pipeline

Streaming Pipeline

🔄 Luồng xử lý dữ liệu

RTSP Stream → ML Model
Camera gửi frame → VioMobileNet-v2.1 phân loại bạo lực, gán risk_score 0–1
Kafka Topic: violence-alerts
Event schema: incident_id (UUID), camera_id, timestamp, risk_score, event_type, location JSON
Flink Job 1 → Fluss (HOT)
INSERT INTO fluss.security.hot_violence_alerts — streaming real-time <100ms
Flink Job 2 → Paimon (WARM)
INSERT INTO paimon.security.violence_incidents — ORC với changelog, 237K+ records
Archive Job → Iceberg (COLD)
PyFlink batch: Paimon → Iceberg với WHERE timestamp < NOW - 7 DAYS

Hồ Chí Minh", "district": "Quận 1", "street": "Đường Nguyễn Bỉnh Khiêm", "lat": 10.78074, "long": 106.70235 } }

⚡ Flink SQL — Dual Sink

-- Job 1: HOT sink (Fluss) INSERT INTO fluss.security.hot_violence_alerts SELECT * FROM kafka_source WHERE risk_score > 0.5; -- Job 2: WARM sink (Paimon) INSERT INTO paimon.security.violence_incidents SELECT * FROM kafka_source;
05 / Streamhouse Architecture

Streamhouse 3-Layer

🔴

HOT Layer

Apache Fluss
⏱ Latency: < 100ms
🕐 Window: Real-time / 1 giờ
📦 Format: Log-structured stream
🔄 Consistency: Exactly-once
🔍 Query: Flink SQL Gateway
-- Hot query SELECT COUNT(*) FROM hot_violence_alerts WHERE ts > NOW() - 1 HOUR
Live streaming · Always on
🟡

WARM Layer

Apache Paimon
⏱ Latency: 3–5 phút
🕐 Window: 1 giờ – 7 ngày
📦 Format: ORC + Changelog
📊 Records: 237,420+ rows
🔍 Query: Flink SQL Gateway (batch)
-- Paimon snapshot warehouse/paimon/security.db/ violence_incidents/ bucket-0/ data-*.orc totalRecordCount: 237420
⚡ Flink compaction · Snapshot-based
🔵

COLD Layer

Apache Iceberg v2
⏱ Latency: 2–3 giây
🕐 Window: > 7 ngày (historical)
📦 Format: Parquet · MinIO/S3
📊 Records: 237,430 rows
🔍 Query: Trino (port 8082)
-- Trino query SELECT COUNT(*) FROM iceberg.security .historical_violence_incidents -- → 237,430 rows in ~2s
🏗 Iceberg snapshots · ACID transactions

🔀 Smart Layer Routing Logic

🔴 HOT"vừa xảy ra", "1 giờ", "live", "realtime"
🟡 WARM"hôm nay", "24 giờ", "7 ngày", "tuần này"
🔵 COLD"tháng trước", "lịch sử", mặc định
# Vietnamese time regex routing if re.search(r'(\d+)\s*(giờ|hour)', query): layer = 'hot' elif re.search(r'hôm nay|24', query): layer = 'warm' else: layer = 'cold' # Iceberg default

11 / Thách thức & Giải pháp

Thách thức kỹ thuật

⚠️
Paimon-Trino Connector không tồn tại
paimon-trino-476.jar không có trên Maven Central
✅ Giải pháp: Disabled paimon.properties, route WARM queries qua Flink SQL Gateway (port 8083)
⚠️
BATCH mode breaks COUNT(*)
Paimon changelog retract records cancel out aggregates
✅ Giải pháp: Không set BATCH mode cho WARM queries. Chỉ dùng streaming aggregation.
⚠️
Archive timing miss
Data ở 16:50 May 2, cutoff 7 ngày = 10:15 May 2 → miss 6.5h
✅ Giải pháp: Dùng INTERVAL '6' DAY cho lần đầu, archived thành công 237,420 records
⚠️
Flink SQL Gateway ORDER BY timeout
SELECT với ORDER BY + LIMIT tạo streaming job không terminate
✅ Giải pháp: Poll nextResultUri chain, lấy UPDATE_AFTER records, timeout gracefully
⚠️
Vietnamese time routing bug
"24 giờ qua" khớp HOT pattern thay vì WARM
✅ Giải pháp: Dùng numeric regex FIRST: r'(\d+)\s*(giờ|hour)' trước substring match
⚠️
Trino SQL syntax incompatibility
DATE_FORMAT() không tồn tại trong Trino (MySQL syntax)
✅ Giải pháp: Dùng format_datetime(), date_trunc(), json_extract_scalar() của Trino
⚠️
Alerts page timeout (MinIO)
100 rows × 3 MinIO HEAD requests = 300 concurrent → timeout
✅ Giải pháp: Skip MinIO lookup cho UUID records (chỉ lookup inc_XXX seeded records)
⚠️
Resource constraints 16GB
10+ services cần chạy đồng thời, OS + Docker ~4GB
✅ Giải pháp: Docker profiles, strict memory limits, ML model chạy máy riêng
