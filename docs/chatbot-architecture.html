3.1 — Ví dụ routing thực tế

→ Fluss HOT
  • "30 phút qua" → 30 phút → HOT
  • "45 phút gần đây" → 45 phút → HOT
  • "bây giờ", "real-time"
  • "1 giờ trước" → 60 phút = ranh giới → HOT
→ Paimon WARM
  • "2 giờ qua" → 120 phút → WARM
  • "24 giờ", "hôm nay"
  • "3 ngày qua", "tuần này"
  • wants_evidence=True → force WARM (frame_url chỉ có ở đây)
→ Iceberg COLD
  • "tháng trước" → ~30 ngày → COLD
  • "năm ngoái", "quý 1"
  • "7 ngày qua" → ranh giới → COLD
Evidence Override (đặc biệt)
  • Phát hiện: ảnh, hình, bằng chứng, frame, video, chứng cứ
  • Nếu layer ≠ Paimon → bắt buộc override sang PAIMON
  • Lý do: chỉ bảng violence_incidents (Paimon) có cột frame_url
  • Token ngắn ("anh") dùng word-boundary \b để tránh match "canh báo"

3.2 — Code routing thực tế

# Bước 1: Numeric regex — ưu tiên cao nhất
pattern = r'(\d+)\s*(phút|giờ|gio|hour|minute|day|ngày|week|tuần|month|tháng)'
match = re.search(pattern, time_period)
if match:
    num, unit = int(match.group(1)), match.group(2)
    minutes = num * unit_to_minutes(unit)   # phút=1, giờ=60, ngày=1440...
    if   minutes <= 60:    layer = "FLUSS"
    elif minutes <= 10080:  layer = "PAIMON"   # ≤ 7 ngày
    else:               layer = "ICEBERG"

# Bước 2: Keyword patterns
elif any(kw in time_period for kw in ["tháng trước", "năm", "quý"]):
    layer = "ICEBERG"
elif any(kw in time_period for kw in ["hôm nay", "tuần trước"]):
    layer = "PAIMON"

# Bước 3: Evidence override — LUÔN về Paimon
if state["wants_evidence"] and layer != "PAIMON":
    layer = "PAIMON"   # frame_url chỉ có ở violence_incidents (Paimon)

4Sinh SQL tự động (Text-to-SQL)

Node generate_sql gửi câu hỏi + schema + dialect hint tới Gemini để nhận SQL phù hợp với từng tầng. Mỗi tầng có syntax khác nhau.

🔥 Fluss (Flink SQL)
🌡️ Paimon (Trino SQL)
❄️ Iceberg (Trino SQL)

Schema (hot_violence_alerts)

incident_id  STRING         -- PK
camera_id    STRING
timestamp    TIMESTAMP(3)
risk_score   DOUBLE         -- 0.0 – 1.0
confidence   DOUBLE
is_violent   BOOLEAN
event_type   STRING         -- shooting, fighting, stabbing...
location     STRING         -- từ temporal join dim_camera
ward_id      STRING
district     STRING

Dialect rules (Gemini nhận được)

  • ❌ KHÔNG dùng COUNT(*) hay SUM() — streaming job không đếm được dữ liệu cũ, luôn trả về 0. Thay vào đó dùng LIMIT N rồi đếm trong Python
  • ❌ KHÔNG dùng ORDER BY — Flink streaming không hỗ trợ ORDER BY trên aggregate
  • ✅ Dùng backtick: `` `timestamp` `` thay vì "timestamp"
  • ✅ Luôn có LIMIT (thường là 50–100) để bounded scan hoạt động
  • ✅ Bắt buộc SELECT location, ward_id, district

Ví dụ SQL tốt cho Fluss

SELECT incident_id, camera_id, `timestamp`, risk_score, is_violent,
       event_type, location, ward_id, district
FROM `fluss`.`security`.`hot_violence_alerts`
WHERE is_violent = TRUE
LIMIT 50

Schema (violence_incidents)

incident_id   STRING   PK
camera_id     STRING
"timestamp"   TIMESTAMP(3)
risk_score    DOUBLE
confidence    DOUBLE
is_violent    BOOLEAN
event_type    STRING
location      STRING
is_deleted    BOOLEAN
frame_url     STRING   -- URL ảnh bằng chứng (MinIO)

Dialect rules

  • ✅ Standard Trino SQL — dùng double-quote: "timestamp"
  • ✅ COUNT(*), GROUP BY, ORDER BY đều hoạt động bình thường
  • ✅ TIMESTAMP '2026-05-22 08:00:00' cho time filter
  • ✅ Tham chiếu đầy đủ: paimon.security.violence_incidents

Ví dụ SQL tốt cho Paimon

SELECT camera_id, COUNT(*) AS total,
       AVG(risk_score) AS avg_risk
FROM paimon.security.violence_incidents
WHERE is_violent = TRUE
  AND "timestamp" >= TIMESTAMP '2026-05-21 08:00:00'
GROUP BY camera_id
ORDER BY total DESC
LIMIT 10

Schema (historical_violence_incidents)

incident_id   VARCHAR
camera_id     VARCHAR
"timestamp"   TIMESTAMP(6) WITH TIME ZONE  -- khác Paimon!
risk_score    DOUBLE
is_violent    BOOLEAN
event_type    VARCHAR
location      VARCHAR

Dialect rules (khác biệt với Paimon)

  • ✅ TIMESTAMP(6) WITH TIME ZONE — không phải TIMESTAMP(3)
  • ✅ Dùng NOW() - INTERVAL '7' DAY cho time filter
  • ✅ Tên bảng: iceberg.security.historical_violence_incidents
  • ⚠️ Nếu Gemini ghi sai tên bảng (e.g. violence_incidents) → _adapt_sql_to_iceberg() tự sửa

Ví dụ SQL tốt cho Iceberg

SELECT camera_id, COUNT(*) AS total_incidents,
       SUM(CASE WHEN is_violent THEN 1 ELSE 0 END) AS violent
FROM iceberg.security.historical_violence_incidents
WHERE "timestamp" >= NOW() - INTERVAL '30' DAY
GROUP BY camera_id
ORDER BY violent DESC
LIMIT 20

5SQL Adaptation — Quirks của Fluss

Flink SQL / Fluss có nhiều hạn chế so với Trino SQL. Trước khi gửi query tới Flink SQL Gateway, trino_client._adapt_sql_for_flink_hot() tự động sửa SQL:

❌ SQL từ Gemini (chưa sửa)
SELECT camera_id, COUNT(*) AS total
FROM fluss.security.hot_violence_alerts
WHERE is_violent = TRUE
  AND timestamp >= TIMESTAMP '2026-05-22 08:00:00'
  AND timestamp <= NOW()
ORDER BY total DESC
LIMIT 50
✅ Sau khi adapt (gửi tới Flink)
SELECT camera_id, incident_id, location
FROM `security`.`hot_violence_alerts`
-- WHERE timestamp filters STRIPPED
-- ORDER BY STRIPPED
-- COUNT() → đếm Python sau khi nhận rows
LIMIT 50

Lý do phải strip time filters

Fluss thực hiện snapshot scan khi có LIMIT: đọc tất cả dữ liệu hiện có trong partition rồi dừng. Nếu thêm WHERE timestamp >= ..., Flink hiểu đây là streaming scan và chỉ trả về các event mới tới SAU khi query bắt đầu — tức là không có dữ liệu nào. Ngoài ra, toàn bộ data trong Fluss (retention 1-2h) đều đã là "hot" nên filtering theo time không cần thiết.

6Thực thi query theo từng tầng

🔥 HOT — Fluss via SQL Gateway

1
Tái sử dụng session (cache 30 min)
Tránh 3 DDL roundtrips (CREATE CATALOG + USE CATALOG + USE schema) mỗi query
2
Dọn zombie 'collect' jobs
Cancel các Flink 'collect' job cũ còn chạy để tránh hết task slots
3
POST statement → poll /status
Gửi SQL qua REST, poll tới khi status=FINISHED
4
GET /result/0 → rows
Bounded scan: data có ngay ở token 0. Dedup UPDATE_AFTER cho streaming aggregates
Latency: 32ms avg (warm session)

🌡️ WARM — Paimon via Trino

1
Convert backticks → double-quotes
Trino dùng "timestamp", Flink dùng `timestamp`
2
Trino query (paimon catalog)
catalog="paimon", schema="security"
3
PyTrino fetchall()
Trả về list[dict] với column names từ cursor.description
Lưu ý: Paimon-Trino connector (paimon-trino-476) chưa có trên Maven Central → queries dài sẽ fallback qua Flink SQL Gateway

❄️ COLD — Iceberg via Trino

1
Adapt table references
Rename violence_incidents → historical_violence_incidents; tổng hợp aggregation tables về raw table
2
Extract time filter
Tái xây dựng: timestamp >= NOW() - INTERVAL 'N' UNIT
3
Trino query (iceberg catalog)
PyTrino với catalog="iceberg" → đọc Parquet từ MinIO
Data chỉ có sau archival (chạy lúc 02:00 UTC, di chuyển data >7 ngày từ Paimon)

Fallback khi infrastructure lỗi

def route_query(sql, layer):
    try:
        if "FLUSS" in layer:   return query_fluss(sql)
        if "PAIMON" in layer:  return query_paimon(sql)
        if "ICEBERG" in layer: return query_iceberg(sql)
    except InfraError:   # connection refused, catalog_not_found, 500...
        log.warning("Layer unavailable → fallback to Iceberg")
        return query_iceberg(adapt_to_iceberg(sql))

Chiến lược tự sửa

🤖 Gemini-guided correction

Gửi: câu hỏi gốc + SQL lỗi + error message → Gemini sinh SQL mới đúng hơn. Ví dụ: nếu lỗi là Column 'frame_url' not found, Gemini sẽ bỏ cột đó ra khỏi SELECT.

🔧 Rule-based fallback

Nếu Gemini API lỗi, dùng regex đơn giản: xóa ORDER BY, xóa cột lạ khỏi SELECT, đổi tên bảng sai, strip TIMESTAMP filter. Ít thông minh hơn nhưng nhanh và không phụ thuộc AI.

8Evidence Retrieval — Truy xuất ảnh bằng chứng

Khi người dùng hỏi về ảnh / bằng chứng (ảnh, hình, bằng chứng, frame, video, chứng cứ), hệ thống thực hiện luồng đặc biệt để trả về URL ảnh từ MinIO.

1
Phát hiện intent (understand_query)
Regex với word-boundary: r'\b(ảnh|hình|bằng chứng|frame|video|chứng cứ)\b'
Token ngắn như "anh" → \banh\b để tránh match sai trong "canh báo"
2
Force layer = PAIMON (select_data_layer)
Cột frame_url chỉ có trong bảng paimon.security.violence_incidents → luôn override sang PAIMON dù time_period ngắn đến đâu
3
Thực thi query Paimon (execute_query)
SQL include frame_url. Rows có frame_url != null → thu thập vào evidence_urls[]
4
Fallback về MinIO nếu SQL fail
Nếu Paimon query lỗi nhưng wants_evidence=True → EvidenceService.list_recent_frames() → list trực tiếp từ MinIO bucket evidence-frames
5
Trả kết quả có ảnh (generate_response)
Response JSON chứa frame_urls[] (list URL) và frame_base64 (ảnh đơn encode base64 nếu 1 incident).
MinIO path pattern: evidence-frames/{camera_id}/{YYYY-MM-DD}/{uuid}.jpg

11Giới hạn và đặc điểm cần lưu ý

⚡ HOT layer

  • COUNT(*) luôn = 0 cho dữ liệu cũ — chỉ đếm event mới từ lúc query bắt đầu. Fix: LIMIT + đếm Python.
  • Session cache 30 phút — query đầu sau restart tốn thêm ~5s để khởi tạo Fluss catalog
  • Zombie 'collect' jobs cần dọn trước mỗi query
  • Không có frame_url, date_id

🌡️ WARM layer

  • Data chỉ có sau khi tiering chạy (mỗi 30 phút)
  • Data mới (<2h) vẫn còn trong Fluss HOT, chưa tier sang Paimon
  • Paimon-Trino connector bị disable → fallback Flink SQL Gateway (~3-5 phút/query)
  • Evidence query (wants_evidence) luôn force WARM

❄️ COLD layer

  • Data chỉ có sau archival (chạy 02:00 UTC, data >7 ngày)
  • Fresh stack = 0 rows trong Iceberg — hoàn toàn bình thường
  • Iceberg schema security không tồn tại trước archival đầu tiên
  • TIMESTAMP(6) WITH TIME ZONE — khác với Paimon TIMESTAMP(3)

🤖 Chatbot chung

  • Latency phụ thuộc Gemini API (~1-3s mỗi lần gọi) — 1 query có thể gọi Gemini 2-4 lần
  • Tiếng Việt có nhiều dạng (giờ/gio/h, ngày/day/d) — regex phải cover nhiều variant
  • COLD query tốn nhiều thời gian nhất (~30-180s) do Trino đọc Parquet từ MinIO
  • Đọc docs/agent-guides/agentic-rag.md để biết thêm chi tiết
